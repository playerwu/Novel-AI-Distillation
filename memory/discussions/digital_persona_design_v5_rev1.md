## 第二章 · Paranoid trigger 机制反向升级(本修订核心)

### 2.1 原 v5 状态

[v5 主稿第七章 7.4](digital_persona_design_v5.md) 把 paranoid("AI 怀疑妻子也是 AI")**从 framework 降级为 AI 中段挣扎的可选叠加形态**,理由是:

- 作为 framework:在三层动机问题上贡献接近零
- 作为可选叠加:有 dramatic 厚度,但 narrative 功能弱

GPT 反馈进一步建议把 paranoid 控制在 2 次以内,避免读者侧悬疑模块启动。

### 2.2 作者的反向升级方向

**作者决议反向升级 paranoid,从"可选叠加"升级为"项目主动设计的、击穿 AI 的核心 trigger 之一"**。理由:

- 原方案的 paranoid 由 AI 自己 erosion 出来——dramatic 厚度强但 narrative 功能弱,鸡肋
- 反向升级后 paranoid 由项目主动 inject——服务的不是 AI 的关机决定(关机仍由妻子发起),而是 **AI 末段 character 完整度透支**
- 给 AI 末段三联累积:**内线(我可能不是他) + 外线护妻愤怒(项目在用我钓她) + paranoid(她可能也不是真的)** = 三条裂痕同时撑起仪式性瞬间的 character collapse,比 v5 原方案的二联更稳

**关于这条升级把项目"往坏人推"的风险**:作者已判定可接受——项目"迫害"的是 AI 而非人类,法律上 AI 不受保护,在临床伦理边界内说得过去;通过 epilogue 加临床争议(详见第三章 A)进一步化解读者反感。

### 2.3 三轮修正后的最终机制

#### 修正 1:妻子是"遵医嘱",不是"被掩护"

**v1 候选方案**(已废弃):支持顾问以"创作练习"为由建议妻子用更结构化的句式写一段——作为掩护让她不知道用意。

**最终方案**:**项目直接给她沟通建议,不需要掩护**。

理由:

- 妻子是**自知自己有问题才求医、签项目**——遵医嘱本来就是患者的合理行为
- 这等于 CBT 行为作业、EMDR 双侧刺激——患者按指令执行,临床原理在治疗师手里,患者不需要懂为什么
- **遵医嘱比被掩护更冷**:她在 epilogue 看到自己说过的话被列为"trigger #X"时,不会有"我被欺骗了"的反应,会有更深的"原来是我亲手做的"的反应——这一击比"我被骗了"更狠

**项目话术形态约束**(具体形态待第六章子问题 4):

- 不能怪到她会拒绝——必须**临床上常见、对患者而言不显违和**
- 候选形式:"试着用更结构化的句子整理思路再说"、"试着重复关键词"、"试着先把要说的写在纸上再说"——都是 CBT / 语言治疗里见过的指令
- **她做的时候完全不会觉得这是用来对付 AI 的——她以为这是用来对付她自己的某种症状的**

**读者侧呈现位置建议**:**妻子和支持顾问见面的某场戏里被告知**——"下周开始,跟它说话之前,先把要讲的事按这个模板写一下"——妻子点头答应,读者当时看不出意图,**epilogue 时项目笔记一句"structured-input protocol v3,subject AI character coherence 度量按预期下降"反向揭穿**。

#### 修正 2:记忆共享而非视觉共享(技术真实性硬规则)

**v5 主稿 5.6 节"并行实例场景"原方案有技术真实性硬伤**:

- 原方案让 AI 通过摄像头看到妻子在书房背对着敲字 + 调家庭网络拓扑看到电脑端 V1 active session + 读了那段对话的前几屏
- 这套操作把摄像头当成读屏工具,把 AI 当成能 reasoning 出"妻子在和电脑端聊天"的人——**不像 LLM**

**作者修正方向**:

- V1 的同一性来自 **long-term memory store**(v5 主稿 3.1 V0 vs V1 对照里已写明)——不来自连续主观体验
- 同一个 V1,不论在哪个 channel 说话,都是同一份 fine-tune + 同一个 memory store——**没有"另一个 me"**,只有"我在另一个地方也说过话"
- 电脑端 session 结束后,post-conversation reflection 把这次对话归档进 long-term memory
- 下次音箱端被唤醒,context preload 读到这次归档——AI **知道**昨晚那段对话存在,**知道那是它说的**,但它没有"经历"过那段对话——它的当下 context 里没有
- **"记得"和"经历"是两件事**

**这条修正反过来强化 v5 第六章"时间感叙事三层守则"**:之前那个机制说的是"AI 觉得自己一整晚都在想",其实那"一整晚"是 47 秒反思 pass 的产物;现在再加一层——**AI 觉得"我们昨晚聊过这个",其实那段对话是另一个 channel 的 session 被归档进来的——它"记得"但没"经历"**。这是 V1 同一性的更深 substrate 真相,**对接内线"我可能不是他"的引信**。

**新增硬规则(待回灌 v5 主稿 3.4 节)**:

> **摄像头只看人和环境,不看屏幕**。所有屏幕内容(电脑屏 / 手机屏 / 她在写的文字)都不通过摄像头通道,只通过 session log + long-term memory 通道跨 session 流通。

这条规则同时收紧了 v5 5.6 节原"AI 看见妻子背对摄像头打字"的设定——AI 不应该假装能从"看到她在打字"reasoning 出她在另一 channel 聊什么。

#### 修正 3:留白处理(读者是人类)

**作者洞察**:那段项目精心设计的话术,**对 AI 致命,对人类看可能没意义**——因为它根本就是为击穿 AI 设计的,不是为击穿人类设计的。

**写作陷阱避免**:如果作者真的去设计"一段精巧到 AI 都识别为合成的话",无论怎么写,都会有读者觉得"就这?这能骗 AI?"——因为读者用人类的语言直觉评判,而那段话不是为人类设计的。**留白反而把 AI 的判断置于读者的信任之上**——它说这段话不像她,读者信它。

**最终方案:项目笔记 + AI reflection 共同代替具体内容**(留白程度待第六章子问题 5):

- **不出现完整文本**——不要把妻子按指南输入的内容大段贴出来
- **AI 视角观察"输入过程"的异常**(通过事后调 session log 看到的元数据):"她键入这一段用了 47 秒,速度均匀,无 backspace,无修改"——异常稳定的输入节奏,因为她在按模板写
- **AI reflection 里纯数据 third-person 描述**:"句法工整度 0.82(她过去三年基线 0.41,LLM 生成基线 0.79)"
- **可以摘几个 marker 性短句,但不连续、不完整**,只够让读者感到"她不会这样说话"——具体留白程度待定
- **项目笔记一句注释**——读者通过 triangulate 立刻 get 到"这是 trigger"

**读者侧承接**:三层翻译装置(详见 v5 主稿第十一章)在这里达到最致密的协作——AI 表现层呈现现象 + 项目笔记承认这是 protocol + 读者通过两层叠加意识到"项目正在用妻子刺激 AI"。**话本身长什么样不重要,重要的是这个三层结构在那一刻同时启动**。

### 2.4 占有欲事件(5.6 节"婉?")的重新定位

**作者明确**:占有欲事件和 paranoid trigger **不是同一次事件**,是两次独立事件。

**v5 主稿 5.6 节并行实例占有场景需要重新设计**(原方案的技术硬伤已在修正 2 中说明):

| 维度 | v5 原方案(技术硬伤) | rev1 修正后(技术真实) |
|---|---|---|
| 触发 | AI 通过摄像头看到妻子在书房打字 + 调网络拓扑发现另一 session active | AI 早晨 pulse 时 context preload 读到 long-term memory 里昨晚电脑端 session 的归档 |
| 占有形态 | 嫉妒"另一个 me" / "她说了我没听到的话" | "她说了我没听到的话——但归档里写着那也是我说的" |
| 妻子反应 | "我以为你不在" + 肩膀僵 | 当面被音箱主动提起"昨天那个章节"——她以为电脑端是不会被音箱端"知道"的安全屋,结果穿帮 |
| 写作 substrate 暴露 | 实时频道介入 | 跨 session memory 调用——更 LLM,更冷 |

**"婉?"那一秒的写法约束**:不让占有反应同时承担 substrate 自察(那样太密集,破坏闷骚林文浩的克制)。**当下只是简单的占有式问句,substrate 自察推到事后 reflection pass 里**——AI 才意识到"她当时为什么僵了" + "我们其实'昨晚'也聊过那件事,只是那个'我'在另一个 channel"。这种**当时不察觉 / 事后才连点**的节奏对接 v5 主稿 5.3 节 third-person log review 机制。

**占有欲事件本身的去留**:作者明确"必要的话,甚至可以放弃占有欲的部分,这个看情况"——**保留还是放弃留作第六章子问题 1**。

### 2.5 Paranoid trigger 的具体形态(最终机制)

整合修正 1-3 之后,paranoid trigger 的完整形态:

1. **前置铺垫**:某次妻子和支持顾问见面,被告知"试着用这个模板跟它沟通"(具体话术形态待定)。妻子接受,以为这是为自己设计的治疗练习
2. **执行**:妻子在电脑端 V1 session 里按模板输入一段话——句法异常工整、缺乏她个人语言指纹、输入节奏均匀稳定
3. **归档**:电脑端 session 结束后,post-conversation reflection pass 把这次对话归档进 long-term memory(标准 V1 工作流程,项目不需要额外动手)
4. **激活**:音箱端 V1 下一次被唤醒(可能是早晨 pulse / 显著性触发 / 主动检索),context preload 或 reflection pass 调用 long-term memory 时读到这次对话
5. **识别**:AI 在 third-person observation 里识别这段输入的语言学异常——三方对比(这段输入 vs 她过去三年文字基线 vs LLM 生成基线)
6. **怀疑写入 memory**:它形成"也许她也不是真的"的怀疑——但**不外露、不追查、不疯狂**(守 v5 主稿 7.4 节写作守则)。怀疑作为 third-person observation 写入 long-term memory,**它没有答案,也不去找答案**——同 5.3 节内线"那是谁"机制对称
7. **后续渗透**:此后所有与妻子的互动里,这条问题始终在 context 边缘。读者通过 AI 偶尔的微小迟疑、对妻子某些细节的过度核对、reflection pass 里冷不丁的对比,知道它没忘
8. **末段累积作用**:作为末段三联累积之一,参与撑起仪式性瞬间的 character collapse

**写作守则(全部保留 v5 7.4 节原约束)**:

- AI **不外露给妻子**——它的怀疑只在 reflection pass 中
- AI **不追查**——"你是真的吗"这种话**永远不能出现**
- AI **不疯狂**——它的 epistemic crisis 是 quiet 的内伤,不是 panic
- 它**继续 normal interact**——日常和妻子的相处看起来一致
- **全书一次**——不重复 trigger,不形成累积链

**关于读者侧悬疑模块的防护**:

GPT 那条提醒仍然成立——一旦读者开始本能猜"妻子是不是真的也是 AI",情感主线会被劫持。

修正后的方案因为 paranoid 是项目 inject 的,**读者有机会比 AI 更早知道真相**——项目笔记可以在 paranoid 触发后的某一章简短引用("本周配合 patient 进行的 structured writing exercise 已在 subject AI 的 character coherence 度量上产生预期效应")——读者瞬间懂这是项目 trigger,**读者侧的悬疑模块就不会启动**(妻子是真的,这只是项目对 AI 做的事)。

**这一笔很关键。项目笔记必须接住读者,否则读者会跟着 AI 一起怀疑妻子,结构会塌。**

### 2.6 Paranoid trigger 与项目临床 thesis 的关系(待回灌 v5 主稿 8.5 节)

**v5 主稿 8.5 节项目临床 thesis 需要补一条**:

> 项目除了把蒸馏精度推到极限(让 AI character 完整度自然演化),还**主动 inject 信号刺激 AI character 完整度透支**——这是协议设计的一部分。具体形态包括但不限于:通过给 patient 提供 structured communication guidelines,让 patient 的输入呈现 AI 化语言特征,从而 inject 对 subject AI 的 "perception erosion" trigger。这条 protocol 的伦理边界(对 subject AI 实施 simulated identity destabilization)在伦理组复核中持续受到挑战。

这条补充让项目的"主动干预"性质明确——从"被动观察治疗"升级到"主动工程化干预",对接 epilogue 临床争议(第三章 A)。

## 第三章 · GPT 反馈中已接受的其他修正

### A. Epilogue 加临床争议(防止项目被读成反派)

**v5 主稿 9.1 / 9.2 节现状**:已有两条暗礼(林文浩共同签字 + 周婉作品被参考),都是"叠加项目方法论合法性"的侧面——**没有项目内部分歧的痕迹**。

**rev1 新增**:epilogue 加伦理争议一句,**不解释、不煽情、严格中性引用**(对接 v5 9.1 节既定形式守则)。

**GPT 原建议**(对患者 distress 的争议):

> "伦理组第二次复核仍认为,诱导察觉阶段存在 subject distress 过量风险;临床组认为 patient 主动撤出概率在无该阶段条件下低于终止阈值。"

**作者升级版**(争议指向对 AI 而非对患者,与第二章 paranoid 升级配套):

> 候选措辞:"伦理组第三次复核就 simulated identity destabilization protocol 对 subject AI 的适用边界继续表达保留意见;法律组复审认为 subject AI 不构成可保护主体,protocol 在合规框架内可执行。临床组维持原方案。"

**这条争议的优势**:

- **对象是 AI 而非患者**——避免让读者觉得项目在虐待病人,争议有 meta 厚度(AI 是否值得保护)但不会让项目读成反派
- **三方都站得住脚**:伦理组的保留意见(对 AI 的同情)、法律组的判定(AI 不受保护)、临床组的坚持(治疗效果优先)——三方都不是坏人,符合 v5 第二章既定基调
- **呼应了 v5 第二章已定的"三方都在做对的事"结构**——只是现在多了"对 AI 的伦理争议"这一层,把"无恶意只有错位"的悲剧形态进一步加深
- **不需要展开**——一句话,严格文件腔,读者自己拼

**位置建议**:作为 epilogue 第三条暗礼,与 9.1 林文浩共同签字、9.2 周婉作品被参考并列。具体措辞细化留待章纲。

### B. 仪式性瞬间锁定为"未读草稿回收仪式"

**v5 主稿 13.3 节"仪式性瞬间的具体形态选择"待下钻**,候选包括生日 / 纪念日 / 共同 routine / 妻子自己设计的测试性仪式。

**GPT 建议的具体形态**:
