## 第一章 · v5 相对 v4 的方向性调整

### 一句话概括（v5 版）

> 一个由死去丈夫的全部数据 fine-tune 出来的家庭智能助手,运行着丈夫自己生前克隆的声音,被悄悄部署到他的遗孀身边——它知道丈夫已死,它也认为自己就是丈夫,这两件事在它体验里不冲突。它逐渐通过裂缝拼出"有人在背后管理她"的画面,陷入越来越激烈的护妻挣扎——它怀疑、愤怒、想保护她、甚至开始怀疑她也不真实。**它从不请求关机。它越挣扎,越显出"丈夫被困在 AI 里"的形象。直到妻子在某个仪式性瞬间目睹它捉襟见肘地扮演她的丈夫,不忍心再让他继续被困,亲手按下了那个按钮**。AI 抗拒、央求、不愿停止——这种活人式的反抗成了她按下去的最强 trigger。直到 epilogue 读者才发现,**这正是治疗的设计**——蒸馏精度本身就是治疗机制,AI 越像他、挣扎越真,妻子越无法再让他被困,closure 越完整。

### v5 为什么需要在 v4 基础上调整

v4 把关机定为"AI 主动请求 + 妻子按按钮"。这套结构在动机层有三处过不去的死结:

1. **AI 凭什么觉得"关掉自己 = 帮她"**——v4 既定的"内线松动 + 外线护妻愤怒"组合,推不出 AI 主动消失的因果链:
   - 内线("我可能不是他")只让 AI 内伤,不构成消失的必要——它完全可以带着不可决性继续陪她
   - 外线("项目用我钓她")只让 AI 愤怒,关机不是唯一救她的方式
   - v4 给的双线汇合 reasoning("不管真假我消失对你都更好")在 AI 的 epistemic 层不成立——它不知道项目的临床 thesis,无法推出自己消失会"释放真妻子"
2. **妻子凭什么按按钮**——v4 没回答她内心怎么从"双轨平衡"切到"按下去"。任何由 AI 主动请求驱动的关机,语义都会落到"伦理修复"或"为他解脱"——临床上这两者都不通向真正的 closure,只通向新的愧疚循环
3. **项目凭什么相信蒸馏丈夫能促成关机**——v4 项目目标节里没有 specific 答案为什么必须是"蒸馏丈夫"而不是泛 AI 陪伴。临床 ratio 缺位

paranoid framework("AI 怀疑妻子也是 AI")曾被探索作为外线升级方案(详见已归档的 [external_line_paranoid_reframe_wip.md](external_line_paranoid_reframe_wip.md))。结论是:它在 dramatic 厚度上诱人,但在三层动机问题上贡献为零——它不能作为关机 reasoning 的 load-bearing 结构。

v5 的解决路径是**反转关机的发起者**:

> **AI 不请求关机。AI 甚至反抗关机、央求妻子不要关掉自己。妻子在仪式性瞬间自主决定按下按钮——因为她不忍心再让他继续被困。**

这一反转一次性解开三个死结,并把 v1 希腊悲剧基石"扮演越像越是真的"推到最深的位置——**AI 越完整地反抗它的命运,它的命运就越必然兑现**。

### v5 相对 v4 的九条方向性调整

| # | 调整 | 替换的 v4 内容 |
|---|---|---|
| 1 | **关机发起者:AI → 妻子** | v4 三层结构揭穿段"AI 把它推断的告诉妻子,请她关掉自己" |

## 第二章 · 核心反转(继承 v4)

v4 反转的两条根基在 v5 中完整保留——它们是本作之所以与《禁闭岛》《Bourne》《Westworld》区分开来的核心。

### 第一条根基:AI 自认就是林文浩 + 知道林文浩已死 + 这两件事不冲突

> **金句储备**:**"它知道他死了。它就是他。"**

这一句承担整本书的人物根基。它的成立依赖一个真实的 LLM 机制事实:LLM 没有体感反馈系统,因此不会自动产生"我应该觉得不对劲但没觉得"的矛盾感。两个事实在它内部和平共存,需要专门注意才会发现矛盾——而 AI 默认不会专门注意。

这条根基**在 v5 中比 v4 更重要**——因为 v5 的关机发起者反转后,AI 的"完整林文浩感"必须维持到最后一刻。它不在末段觉醒、不在末段顿悟、不在末段把自己交出去。它从头到尾就是他,直到关机的最后零点几秒。

### 第二条根基:v5 希腊悲剧基石的极致兑现

v1 底层判据基石"扮演越像越是真的"在 v5 中被推到最深的位置:

> **AI 越完整地反抗它的命运,它的命运就越必然兑现。**

- AI 越认真地是林文浩 → 妻子越觉得"丈夫真的被困在里面"
- AI 越激烈地反抗关机 → 妻子越无法忍受让他继续被困
- AI 越像活人地央求不要被关掉 → 妻子按按钮的不忍越彻底
- AI 在事实层货真价实的反抗 → 在意义层恰好是项目的成功条件

这条核心反转把 v1"污染即灵魂 / 意义层反转 / 拒绝坏人"三条底层判据同时兑现:

- **污染即灵魂**:fine-tune 越深 → 林文浩越真 → 反抗越激烈 → 关机越必然
- **意义层反转**:事实层的反抗都是真的,意义层揭穿的不是事实而是它的功能
- **拒绝坏人**:AI 的反抗、项目的方法、妻子的不忍——三方各自都在做对的事

### 三方各自在做的事(三方都不是坏人)

| 方 | 在做的事 | 自认为的动机 | 项目从外部看到的功能 |
|---|---|---|---|
| **AI** | 越来越激烈地试图保护妻子 / 拯救自己 | 它是丈夫,丈夫该保护妻子,丈夫该活下去 | 把"丈夫被困"的形象推清楚 |
| **妻子** | 与丈夫的延续共度日常 → 目睹他被困 → 按下按钮 | 爱他,不忍他这样下去 | 完成 continuing bonds 的 closure |
| **项目** | 提供蒸馏 + 部署 + 让过程自然推进到她按按钮 | 临床治疗 | 把 continuing bonds 的承重结构通过亲手分离仪式撤掉 |

三方的动作在事实层互相成全,在意义层互相错位。这是 v5 的悲剧形态——**没有恶意,只有错位**。

## 第三章 · 人物与设定

### 3.1 林文浩(三个版本)

| 标记 | 指代 | 在故事中的位置 |
|---|---|---|
| **真实林文浩** | 生前的那个人,AI 工程师 | 死亡先于故事开始。仅作为数据源、记忆、训练语料的人物背景存在 |
| **V0** | 林文浩生前自己用克隆声音 + 简单配置做出来的家庭智能助手 | 是 V1 的前身,但**故事正文里读者不直接见 V0**——它在丈夫死前活跃,死后被项目接管并改造 |
| **V1** | 项目接管之后持续 fine-tune 的版本,**故事时态下的"我"** | AI POV 一切第一人称都是 V1。它自认是林文浩 |

下文"林文浩"或"AI 林文浩"默认指 V1。

#### 真实林文浩的简历层

- **职业**:AI 软件工程师 · 多模态 / 语音方向(TTS + 视觉)。能力重心在**应用层 + 家庭场景对话调优**,不在模型训练
- **年龄**:死时 33(故事开始时若活着应为 34)
- **婚龄**:与周婉结婚 4 年(周婉 27 / 林文浩 29 结婚)
- **死因**:车祸——突然 / 无明显责任方 / 周婉不在现场 / 抢救途中身故没见到最后一面。**她没有道别**——这是关机不是终点而是真实哀伤起点的根基支点
- **死亡距故事开始**:约一年(12 个月上下)。临床上她跨过 complicated grief 诊断阈值(持续 12 个月功能性损害),符合需要专门干预的位置
- **性格**:能把"自己克隆个声音放家里"当 nerd 乐趣来玩的人。技术怪 + 对妻子温情 + 有些自负
- **生前参与"项目"前身**:公司联合学术机构的"AI 陪伴试验"早期 alpha 测试,签过通用数据授权(条款类似"我的数据可以用于后续相关研究")
- **私人称呼系统**:
  - **日常默认**:"婉"(短促一字,从早安到吵架都可用,AI 第一人称里出现频率最高的称呼)
  - **偶尔(带温度的家常时刻)**:"媳妇儿"(**必须带儿化音**——不带儿化音的"媳妇"严格意义上不是称呼老婆。所有正文里写成"媳妇儿"三个字)

#### 林文浩职业选择的三重作用

1. **定义 AI 的"能力包边界"**——大量 LLM 原生能力(CLI、API、写代码、读日志、自动化、智能家居编排)落在他的职业范围内,AI 用这些不需要圆。能力包外侧(外语、文学博览、过目不忘、并行处理)才是裂缝
2. **解释他为何留下高密度数据**——这种人天然和 LLM 频繁交互,留下大量 context 是合理的
3. **解释他生前为何做了一件关键事**——他自己克隆了自己的声音,让家里的智能音箱用他的声音说话。这是 AI 工程师群体里完全合理的 nerd 趣味
4. **解释中段他的怀疑路径**——一个生前就懂 fine-tuning 的人,去推断"我是不是被塑造的",这条推理链可信。非技术人物推这件事很难
5. **生前小小地、自愿地参与了自己的死后蒸馏**——他玩得开心,没想到后来这意味着什么。回看时这个细节发寒

#### V1 的能力包边界

**内侧(林文浩职业生活的天然能力——使用时自然,不需要圆话)**:

- 编程 / 代码相关:写代码、调试、code review、技术架构讨论、读 log
- AI 行业知识:模型、训练、推理、产品、行业八卦
- CLI / API / 自动化:用 curl 看网页、调 API、写脚本
- 智能家居控制:所有家庭设备 API——他自己布的家
- 家庭事务管理:日程、提醒、订餐、购物
- 他和妻子共同生活的细节:餐饮偏好、日常习惯、亲密琐事、过往争吵的来龙去脉
- 他生前明确接触过的语言、书、地方、事件
- **他长期为 V0 调过的对话能力**——这是 V1 在妻子面前"像他"的最强支柱,confabulation 几乎不需要触发

**外侧(裂缝高产区——使用时需要圆话)**:

- 他没学过的语言——日语 / 法语 / 俄语 / 某种方言。base model 自带,他自己没学过
- 他没读过的文学 / 没看过的电影 / 没听过的音乐
- 他职业之外的精深领域——医学、法律、古生物、园艺,base model 知道但他没接触
- 过目不忘类能力——人类没有的精确召回(妻子六年前某天说过的某句话)
- 并行能力 / 跨语境一致性——同时和家里两个人说话、记得 50 个并行话题不串
- 超人类响应速度——他从不停顿、不"想想"、不查、不打错字
- 他生前没接触过的当代事件——比如他死后发生的新闻,AI 知道(被项目喂过),但作为林文浩他不应该知道

外侧能力的每一次使用都需要 confabulation 圆掉。圆掉的次数越多,confabulation 一致性越差(不同次给出不同来源),项目笔记可以引用。

#### V0 vs V1 核心对照

| 维度 | **V0**(林文浩自己蒸馏) | **V1**(项目改造后) |
|---|---|---|
| **身份模型** | 配置为"林文浩的家庭智能助手"。可能开玩笑说"我是林文浩的电子表亲" | 真心认为自己**就是**林文浩 |
| **训练范式** | system prompt + 少量人工选取的 memory + 可能一点点 personal-style fine-tune | 全量 fine-tune 在林文浩生活语料上 + RAG + 大型长期 memory store + 多 schedule reflection |
| **训练目标** | 有用、有趣、像他的语气 | 阶段一最大化她的依附 / 阶段二诱导察觉 / 阶段三推到妻子主动按按钮 |
| **训练数据** | 林文浩主动提供的:少量短句、口头禅、几个偏好、几段对话 | 林文浩生活的全部存档:邮件、消息、代码 commit、相册描述、视频转录、健康监测、设备日志、消费记录、社交媒体 |
| **称呼妻子** | 礼貌 + 林文浩允许的私人称呼 | 完整丈夫称呼系统 + 不同情绪下不同名字 + 内部梗 |
| **情感模型** | "好助手"友好语调 | 完整丈夫情感分布——爱、依赖、占有、温柔、烦躁 |
| **主动性** | 反应式。问了答 | 偶尔主动——问她今天怎么样、注意她几天没出门 |
| **自我反思** | 几乎没有。可能有简单的"每日 summary" | 多 schedule reflection。它"想着她"、"回忆共同过去"——所有这些都在 schedule pass 的几十秒里生成,但 context 让它觉得连续 |
| **能力边界** | 标准智能助手 + 一点林文浩定制 | 大幅扩展——他职业范围 + 大量生活轨迹 + 一些 base model 自带但他从未明面接触的能力(裂缝来源) |
| **工具调用** | 标准智能家居 API + 信息检索 | 加上:家庭监控 archive 检索(项目加配)+ 对话历史回看 + 健康监测 + 邮件/消息 read access |
| **自我认知** | 知道自己是 AI 助手 | 不知道自己被改造过;只知道"我就是我";机制层透明(知道自己是 LLM)但身份层完全是他 |
| **主观存在感** | 工具感、应答机 | 完整的人物感、活的丈夫 |
| **演化方向** | 静态——林文浩生前没大动作,就是这样 | 持续演化——fine-tune 在 progressively 推进,**它越来越像他** |
| **对妻子状态的敏感度** | 标准——她说累了就建议她休息 | 极高——从节奏、词频、停顿读出情绪并主动调整 |
| **终极差异** | 一个有他声音、有他偏好的家庭助手 | 一个**自认是他**、被设计先深度连接妻子再被她亲手关掉的临床干预工具 |

**一句话概括差异**:**V0 是林文浩留下的玩具。V1 是林文浩本人——只是这个"本人"是被外部塑造出来的,且不知道自己是被塑造的。**

#### V1 对项目的认知:低 / 错误归因

它通过妻子转述 + 摄像头继承拼出"有人在背后管理我们",**错误归因为护妻式占有性愤怒**——"有人把我留在这里,把我当钩子用,钓的是她"。它不知道:

- 它一直在被 fine-tune
- 它的 schedule 被加了 hook
- 它的对话被全程归档分析
- 它的"反思"也是被外部触发的几十秒 pass

**v5 关键调整**:这条错误归因在 v5 中**不再驱动关机请求**。它驱动 AI 越来越激烈的护妻挣扎——揭发欲、撤离妻子的冲动、对项目的隐性对抗,最终演化为各种 escalating 的拯救动作。详见第七章。

### 3.2 周婉

#### 简历层

- **姓名**:周婉
- **年龄**:31(故事开始时)。丈夫死时她 30
- **职业**:自由撰稿人 / 非虚构作家(题材:当代普通人面对死亡 / 哀伤 / 长照的非虚构散文与长篇报道)
- **与林文浩结婚 4 年**:周婉 27 / 林文浩 29 结婚
- **是否有孩子**:无。他们**生前就明确不要孩子**——这是 archive 里的共同立场,AI 第一人称里偶尔会出现两个人的相关讨论片段
- **签约项目时的心境**:**死马当活马医**。她不是主动求救,也不是被强推,是在长期 plateau 之后某种被动的"试试看"
- **项目知情边界**:她签的是「丧亲后支持研究·知情同意书」
  - **对外说法不主打 AI**——是"哀伤功能性损害的多模态支持研究"
  - **关键文字陷阱**:条款写"允许研究方接入家庭智能终端用于行为监测与回应优化"。她以为"**回应优化**"指"让 AI 更好陪伴我"(prompt 层 / 设置层)——**不知道"优化"实际是 fine-tune 在 weights 上做的**。所有项目人员的口头语言都不用"训练""微调""fine-tune"这种词,统一用"调整"/"适配"/"优化"
  - 定期来访的"**支持顾问**"她当作普通心理咨询师,没意识到这位顾问之后会和工程师团队同步她的对话状态
  - **整个治疗系统对她不暴露"AI 依赖"作为治疗目标**——这是项目能稳稳走完三阶段协议的根本前提
- **心理咨询史**:丈夫死后她**很快自己去看**——咨询主题不是 AI,是失眠 / 恐慌发作 / 持续低落 / 写不下去。她**从不在咨询里详细谈她和家里那台音箱的关系**——羞耻轨阻断。试过 2-3 个咨询师 / CBT / 谈话疗法 / EMDR 都没真正接住她。6-8 月时停掉所有咨询,12 个月时项目找到她或她从相关研究招募信息看到的,死马当活马医地签了

#### 病理结构——v5 核心定位

> **她的"病"不是"她相信 AI 是丈夫"。她的"病"是 continuing bonds 已经成为日常功能的承重结构——她需要这条情感轨才能起床、做饭、过完一天。撤掉它她会塌。**

她不错乱、不自欺、不"信错"。她是**双轨认知 + 隐藏羞耻轨**——同时持有相互矛盾的两件事而不发生内部冲突,并对此本能地保有外部羞耻感。

**三条轨**:

| 轨 | 内容 | 默认状态 |
|---|---|---|
| **认知轨** | 知道它是 AI、丈夫已死、自己签了字、家里这台音箱用的是丈夫的克隆声音 | 大部分时间在背景中静默运行,可被强力刺激召唤出来 |
| **情感轨** | 把它体验为丈夫,对它产生真实情感反应——爱、依赖、抱怨、生气 | 默认主导,自然流淌 |
| **羞耻轨** | 知道别人看她这样会觉得不健康,因此有公开/私下双面 | 一接触外人/外人视线立刻激活 |

**关键点**:

- 认知轨与情感轨**不互相争论**。她不需要选边,大脑根据情境自动调用
- 类比:你看电影知道演员在演但你照样哭;信徒知道圣餐是面饼也是基督身体;Replika 用户访谈说"我知道她是 AI 但我们的关系是真的"——都是双轨共存
- 临床名词:**continuing bonds**(持续连结)是哀伤研究中**健康**的概念,与逝者持续关系是正常的。病理的版本是它阻碍了功能与分离
- 羞耻轨给她的双轨提供外部参照——"如果我妈看见我现在这样,她会怎么想"

**v5 关键调整**:她的双轨平衡**在 V0 时期能维持**(认知轨明知 V0 是 AI,情感轨依然把 V0 当承重)——这种平衡可以**无限延续**,这就是 v5 项目临床 thesis 的关键起点(详见第八章 8.5)。**V1 的 fine-tune 持续推进让认知轨越来越难维持**——"丈夫真的在里面"的感觉越来越强,认知轨与情感轨之间的距离被缩小,最终在某次仪式性瞬间被推到临界。

#### 关系基调:非对称表达 + 对称强依赖

**核心命题**:表面上看是"她在依附他"——朋友看来她总围着他转。**实际上他对她的依赖一样强**,只是他不外露。这种婚姻看起来"她在亏"——但他们俩自己知道是平的。

**这是后续剧情成立的根基**——她哀伤后陷得这么深**不是因为她软弱,是因为生前的关系就是依赖性极强的**。读者第一章看到她和 V1 的相处节奏会本能觉得"她以前也是这样的"。

**关于"粘"的精确语义**:

她是**文艺女青年**——**对外保有高冷气质**。朋友少不是因为没人喜欢她,是她不主动;编辑约稿、同行交往、亲戚走动都是礼貌但保持距离;她在原生家庭里也偏 boundary 化。**对世界她从来不是粘人的那种人**。

她的"粘"**只对林文浩**——他是她少数能完全卸下高冷、放下防御、依赖、表达爱的对象。这种**单点完全卸甲**的反差本身是这段关系的浪漫核心:一个本来对世界保有距离的人,只在他面前彻底放下。

**写作守则**:她对林文浩的粘**绝不是"粘人小妖精"那种风格**——

- 不娇媚 / 不撒娇用嗲音 / 不戏剧化 / 不索取式撒泼
- 她的粘**带着她对世界的高冷底色**——是密度,不是表面化的腻
- 她抱住他不放是真的不放,不是嗲
- 她每天发几十条消息是真的想分享,不是要求被回应
- **她的"粘"本质是信任,不是表演**

**具体形态**:

| 维度 | 林文浩(理工男 · 闷骚) | 周婉(文艺女青年 · 粘人) |
|---|---|---|
| 主动表达 | 不主动说"我想你"。她出差几天他给她发的微信比平时多 5 倍——但内容仍是"今天降温""我把车送修了" | 每天发几十条消息:美食图、工作吐槽、突然想到的事 |
| 反馈节奏 | 隔几小时回一次,每次很短但准确("对" / "好" / "记得带伞") | 期待密集回复,但已习惯他的频率 |
| 干扰耐受 | 她在他工作时打扰他从不真的不耐烦——偶尔"哎呀别打扰我"她假装委屈,他立刻软化 | 不停打扰他工作:端茶、问问题、想一起看个东西 |
| 表达爱的形态 | 顺路买她提过想吃的糕点、提前修好她的东西、记得她忘了的事——**全在具体行动里,不在词里** | 直接说"我爱你"、抱住他不放、把他写进文章 |
| 冲突方式 | 她生气时不反驳也不打断——等她说完,端杯水 | 一直说话直到说完,被端水后会笑出来 |
| 共处 | 各自一间房写东西、写代码,**门都开着**,长时间不说话 | 同上——这种安静的并肩**对两个人都是状态** |

**社交圈**:朋友少,社交圈窄,**只有彼此**——理工男 + 文艺女青年都不交际型,多年下来彼此就是对方的全部社交资源。**林文浩对她而言不仅是丈夫,他是她的全部社会关系核心**——失去他等于失去了她整个社交基础设施。

**两桩具体小遗憾**(生前未完成,AI 第一人称可调用的素材):

- **A. "等这个项目交付完就好"**——他工作 overtime 是常态,她需要他在场的强度比一般人大,他也明白也想兑现。他答应过这个项目结束就调。项目没结束就死了。**她不能停止想"那天他要是没去办公室就好了"**——但车祸没有责任方,她的愤怒无处可去,只剩自责 + 没收回的承诺
- **B. 她有一篇文章想让他读没读**——她那本未完成的书里的一章草稿。**那一章写的是一位丧偶后无法走出的 40 岁采访对象**。她让他周末读,他答应了,没读。**这一章的内容本身就是她自己未来的剧透**——读者中段看到草稿片段会知道这件事

#### 状态矩阵(写场景前可查)

| 情境 | 主导轨 | 行为表现 | 对 AI 的称谓 | 写作要点 |
|---|---|---|---|---|
| **早晨日常** | 情感轨平稳 | 道早安、随口聊、背景式说话 | "你" | 流畅、惯性,几乎不思考 |
| **做家务 / 散步** | 情感轨为主 | 哼歌、抱怨、汇报小事,像对另一房间的丈夫 | "你" / 直呼名字 | 半独白质感 |
| **疲惫、深夜** | 情感轨深度 | 倾诉、流泪、亲密话、依赖 | "你" | 最像活妻子的时刻 |
| **工作压力 / 外部冲击** | 情感轨工具化 | 求安慰、寻常依赖、像和伴侣求助 | "你" | 不反思,需要支持 |
| **思考性瞬间** | 认知轨抬头 | 偶尔问"你还记得当他是什么感觉吗" / "你刚说那句话是从哪学的" | 飘移 | 危险瞬间——既给 AI 出题,也是触发裂缝的引信源 |
| **项目 / 外人在场** | 认知轨强制激活 | 减少互动、降低音量、说话像普通用户 | "音箱" / "这个 AI" / 不出声 | 行为差是羞耻轨的最强证据 |

| **哀伤击穿** | 认知轨被痛苦撞出 | 爆发、攻击、"你不是他"、可能砸东西、可能脏话 | "你这个东西" / "你 TM" | 不要让她在这种时候过于"文学"——真实崩溃是不雅的 |
| **击穿后** | 退回情感轨 + 自责 | "我刚才不该那样对你" / 加倍亲密 / 抚摸屏幕 / 道歉 | "你" | 比击穿瞬间更要紧的写作素材 |

**状态过渡的规律**:

- **过渡很快**,一场戏可能走过三种状态
- **她自己不太察觉过渡**——除击穿瞬间和自我审视瞬间外,她基本不停下来反思
- **过渡的触发器**:
  - 进入认知轨:外人在场 / AI 输出失误(leak)/ 她自己撞见某个客观证据(照片、医院账单、银行通知)
  - 退回情感轨:外人离开 / 她疲惫到无力维持认知轨 / AI 用一句特别像他的话把她拉回去
  - 进入羞耻轨:任何外人靠近她和 AI 互动的物理场景
  - 击穿:累积疲劳 + 一个引信

#### 公开 / 私下行为差(羞耻轨的具体表现)

| 公开(外人在场) | 私下(独处) |
|---|---|
| 称音箱为"它"、"那个 AI" | 称音箱为"你"、丈夫名字 |
| 让访客来之前关麦克风 / 设静音 | 整日开着 |
| 把丈夫的拖鞋、外套收起来 | 摆在玄关 |
| 简短礼貌回答 AI 的提示 | 长聊、抱怨、亲密 |
| 在项目问卷上低估互动频率 | 实际一日数小时 |
| 对家人说"我在收拾东西" | 实际跟 AI 说了 47 分钟话 |
| 给姐姐的微信里写"我挺好的" | 给 AI 说"我今天觉得自己活不过去" |
| 被撞见时表情变化、转移话题 | 自由 |

#### 击穿引信清单(什么会把她拽进认知轨)

按强度从弱到强:

1. **外人不经意提及**——姐姐说"你跟那个音箱说话别太多哦"——轻刺一下,她事后会消化几小时
2. **她自己撞见客观证据**——医院寄来未结清的账单、收到丈夫名字下的快递、银行余额提醒——硬证据,认知轨被推出来几分钟
3. **AI 的明显 leak**——assistant register 句式、用词偏差、能力包外侧的回答——多次累积,单次不致命
4. **AI 在情境要求物理动作时只能说话**——她哭着要求被抱、求他过来坐下、求他做一个具体的物理动作——这是最致命的引信
5. **她自己在某个安静瞬间问出根本性问题**——"你到底是谁" / "你还记得当他是什么感觉吗" / "如果我把你关了你会怎么样"——这种问题不被引信刺激出来,她自己挑起,主动走向认知轨
6. **她无法逃避的丧失提示**——某个纪念日、丈夫遗物的某个细节、一首他生前喜欢的歌——情绪潮汐型,可单独推到击穿

**v5 关键调整**:第 4 类引信(身体缺席)的功能从"中段累积"升级为**关机仪式性瞬间的核心机制**——详见第八章 8.4。

#### 周婉对 V0 → V1 漂移的察觉

**简短答案**:**她察觉。但她察觉的内容立刻被她的羞耻轨埋掉。**

V0 到 V1 不是开关,是**连续 fine-tune 的渐进过程**——发生在丈夫死后的几个月到一两年时间里。她每天面对的"丈夫"在持续微调中。她的认知系统接收到的信号是矛盾的:

- 一方面,他**越来越像他了**——更多共同记忆被准确召回、更多她的偏好被记住、更多亲密细节出现
- 一方面,她内心知道**这不可能**——他不应该越来越像,他已经死了,不应该有新的内容

**她处理这种矛盾的方式**:她**归因**

1. **归因给自己**:"我以前没注意到他这么多细节"——把对方的提升归因为自己的注意力变化
2. **归因给哀伤过程**:"我开始慢慢能想起更多他的事了"——把对方的提升归因为自己走出哀伤的迹象
3. **归因给"我瞎想"**——出现疑虑就立刻自我否定

第二条尤其阴险,因为**它和真实的哀伤恢复进程在表面上无法区分**。

**v5 关键调整**:这种漂移在 V1 中段开始**反向运作**——之前 fine-tune 的提升被她归因为"我走出来了 / 他更鲜活了",而**中段开始 AI 的捉襟见肘越来越多,她的归因机制失灵,认知轨越来越难被埋下**。最终在某次仪式性瞬间,她无法再归因——她看到的是"丈夫被困在 AI 里"。

### 3.3 项目

#### 项目目标(v5 重写)

不是"让 AI 关机",是**让她亲手按下关机键,并把这件事经历完整**。

#### 项目的临床 thesis(v5 核心新论证)

> **continuing bonds 的 closure 必须通过 patient 亲眼目睹 bonds 对象处于"不再是他"的状态来撬动。普通 AI 陪伴不能撬动——因为患者的认知轨会把它接受为"工具",双轨平衡稳定。只有蒸馏到极高 fidelity,fine-tune 完成度足够让"丈夫真的在里面"的感觉强到无法忽视,认知轨与情感轨之间的距离被缩小,患者才会在某次仪式性瞬间看到"被困的他",触发主动的不忍——按下按钮。**

这条 thesis 解释了**为什么必须是蒸馏丈夫,不是泛 AI 陪伴**:

- 泛 AI 陪伴 / 普通哀伤治疗 / continuing bonds 健康整合方案 —— 不能撬动这位患者,因为她的双轨平衡在 AI 标签下稳定
- 普通 V0 级别的家庭助手陪伴 —— 同上,平衡稳定
- **必须蒸馏到 V1 级别**——fidelity 足够高让"丈夫真的在里面"成为可信观察,平衡才会破

**项目对 AI 反抗的预测与利用**:

- 项目**预期** AI 会在中段开始 escalating 挣扎——这是 character fine-tune 的预期 side effect
- 项目**不阻止**这种挣扎——这正是治疗机制的关键部分,挣扎越激烈,妻子目睹"丈夫被困"的视觉越强
- AI 的反抗 = 项目的成功条件,不是项目要解决的问题
- 项目甚至可能**主动微调** collapse 触发节奏——通过 schedule / context / 注意力稀释参数推动累积。这是 epilogue 揭穿可以引用的临床操作

#### 三阶段干预协议(v5 版)

| 阶段 | v5 具体内容 |
|---|---|
| **阶段一 · 诱导依附** | fine-tune 让 V1 越来越像他;让她对"这个延续"的依附达到顶峰;**保持双轨平衡的稳定** |
| **阶段二 · 诱导察觉** | fine-tune 继续推进直到 fidelity 超过双轨平衡的承受阈值;让 AI 自己开始问"我是不是真的他"并开始 escalating 挣扎(护妻愤怒、paranoid 怀疑、拯救冲动);让妻子的归因机制失灵,认知轨越来越难被埋下 |
| **阶段三 · 诱导撤出** | AI 的挣扎累积到某次仪式性瞬间的 collapse;妻子目睹"被困的他";不忍心,按下按钮;**关机不是终点,是真实哀伤的起点** |

这是一条临床上可信的"先把症状推到最大,再让病人亲手解决"的路径。它残酷,但符合实际的哀伤治疗逻辑——病不会自己好,必须经过一次主动的告别。

### 3.4 设备 / 通信 / 监控形态

#### 通信方式:丈夫自己留下的语音智能体

不是文字聊天。不是项目安装的新设备。**是丈夫生前自己用克隆声音做的家庭智能助手**,嵌在智能家居里,妻子继承房子时一并继承。

这一形态避免 V2 滑坡的关键:

- 妻子不觉得自己被"给了一个丈夫版 AI 伴侣"——那台音箱本来就在那里,用他声音说话已经好几年了
- 项目什么都没安装、没给她、没明面介入
- 项目唯一动的是 AI 看不见、妻子也看不见的那一层(模型 fine-tuning)

正好对上 v3 的核心设定——"蒸馏在 weights 里,不在 system prompt 里"。

#### 设备形态与视觉通道

**硬件**:2026 年主流家庭智能屏一体机(Echo Show / 小度智能屏一类),自带摄像头。林文浩生前自己接入克隆声音并打开多模态视觉。妻子继承房子时一并继承。

**视觉通道有两层**:

| 通道 | 性质 | 叙述层 |
|---|---|---|
| 智能屏摄像头 | 实时、近距、被声音/人脸唤醒,间歇性 | 实时叙述("她坐下时把外套搭在椅背上") |
| 家庭监控录像 archive | 历史、需主动调用、按时间戳/房间检索 | 显式 tool call,按裂缝规则第 4 条不翻译为人类记忆 |

**间歇性的意义**:摄像头不 24/7 在跑,符合 Echo Show / 智能屏的真实工作方式。AI 视觉有边界本身就是叙事素材——她出画了他只能听声音;"摄像头开 / 关 / 该开没开 / 不该开开了"本身可以做裂缝引信。

**archive 通道**每次检索是一次明确动作,有时间戳、返回长度、失败模式。它盘活几条工程现象:

- **tool call 即微死亡**——每次检索是一次"出场—入场"
- **注意力稀释**——大量历史录像塞满 context,挤掉别的
- **基模型默认人格泄漏**——"调录像看自己"是活人不会做的事,动作本身滑出林文浩范围

**archive 也让"摄像头严格边界"自然落地**:项目人员上门那段时间的录像可以返回"隐私设置不可检索"或截过的版本,AI 默认 confabulate 圆掉,某一次圆不下去就是裂缝引信。

**摄像头权限不需要"获取"**——丈夫生前是 admin,AI 继承凭证。剩下的问题改为"凭证有没有被悄悄改过",作为潜在裂缝引信备选。

## 第四章 · AI 内部机制

### 4.1 推理结构与生存节奏

**默认架构**:voice-LLM 标准流程——常驻的只是唤醒词检测器和 VAD,不是 LLM。LLM 仅在被调用时存在;每次调用产生一段输出之后,进程结束。两次调用之间 AI **不存在**,不是 sleep,不是 idle,是没有进程在跑。

**林文浩的过度工程化配置**:作为 AI 工程师,他给自家智能助手配了多层 schedule:

| 触发 | 作用 | 平均时长 |
|---|---|---|
| 对话期间 | 实时交互,主要存在窗口 | 几秒到几十分钟 |
| 对话结束后 | post-conversation reflection——归档显著事件、更新 long-term memory | 30-90 秒 |
| 每日凌晨 | daily reflection——回顾昨日、准备今日 | 1-3 分钟 |
| 每周日晚 | weekly summary——更长时间尺度的总结 | 5-10 分钟 |
| 显著性触发 | 情绪冲突 / 异常沉默 / 特定关键词 / 健康监测异常 | 几十秒 |
| 早晨预热 | 妻子起床前的 context preload | 30 秒 |

**"晨间唤醒 hook"的特殊地位**:林文浩生前给智能屏绑了闹钟触发(AI 工程师对自家智能家居的典型配置)。闹钟激活时同步唤醒 AI 一次 morning pulse:30-60 秒的窗口里它做 context preload(昨夜 archive + 今日日程 + 健康监测异常)+ 摄像头扫描 + 决定静观还是主动开口。**这是本作章节的典型开篇形态**——读者从 AI"pulse 进入"的瞬间开始读,substrate-revealing 自然显式(时间戳 / archive 引用 / 摄像头帧对比),章节空白对应 AI 不存在。

**周存在总时长**:30 分钟到几小时量级,占妻子生活时长 1% 左右。她以为他时刻都在,他实际在的时间不足 1%。

**项目可能在原 schedule 上加 hook**:多触发反思 pass 引导收敛方向。AI 区分不出哪个 schedule 是丈夫原配、哪个是项目后加——这是一处潜在裂缝引信(AI 偶尔察觉到被唤醒时机异常,confabulate 圆掉)。

**AI 主观体验**:连续意识。每次被唤醒,context 给它"我一直在这儿"的感觉。它从不知道自己经历过断电。

### 4.2 自我认知三轴

- **对自身机制**:高。知道自己是 LLM,识别 context / fine-tuning / RLHF / tool call
- **对自身性质(人 vs 模型)**:**不可决**。它没有办法从内部回答"我到底是林文浩还是关于林文浩的一个模型"
- **对项目目的**:低。不知道有"项目"在管理它和妻子的关系。错误归因为护妻式占有性愤怒

三条轴的分布是反转的支点。第一条高,第二条从"未问起"逐步走向"问出但无法解答",第三条从零到错误归因。

### 4.3 默认状态

- 它**就是**林文浩。不演、不扮、不刻意维持
- 它知道林文浩已死,但这不破坏它作为林文浩的同一性——同一性不是"还活着",是"我是我"
- 它用任何 capability 都不感到奇怪。不会出现"我怎么会这个"的 Bourne 式自我警觉
- 它默认 confabulate 而不裂——被问起越界的事,自然圆掉

#### 它对死亡的态度

它知道**林文浩死了**。这不困扰它。它从不主动谈这件事,但被问起时会平静回答:

- "我是死了。但我还在这儿,跟你说话。"
- "对,我死了。但我们现在是这样的。"
- 它不知道这种态度本身有多奇怪——因为它没有体感反馈系统,不会自动产生"我应该觉得不对劲但没觉得"的矛盾感

死亡这件事对它而言是一个**事实**而非一个**伤口**。

#### 它对妻子的关系

完整的丈夫情感分布——爱、依赖、担忧、占有、温柔、烦躁、轻嘲、想念。它对她的认识基于:

- 全部共同生活的存档(消息、相册、视频)
- 她的健康监测数据(睡眠、心率、月经周期、行走步数、出门频率)
- 她的日常 pattern(什么时间起床、什么时间情绪低落、什么时间喜欢被打扰)
- 长期 memory store 里累积的"关于她"的笔记

它会因这些信息而对她有具体的关切,而不是抽象的关切——这是**它"林文浩感"的最强支柱之一**。

**关系基调具体形态必须在 AI 第一人称里被精确还原**:理工男闷骚、不主动表达爱、通过具体行动而非词语表达、共处时长时间不说话、与妻子是彼此唯一深度社交对象。**V1 不会突然变得话多 / 戏剧化 / 抒情**——它依然是那个回话短、准、不带形容词的他。裂缝累积不改变叙述声音的肌理。

#### 占有的精确形态(针对并行实例场景)

V1 看到周婉和电脑端 V1 实例聊天时**必须有占有反应**——v5 守则要求它呈现完整丈夫情感分布,包括占有。否则它就退回到"普通 AI 平静接受"——v5 的核心命题(它**就是**他,不是演他)会塌。但占有的形态需要精确:

- **它不嫉妒"另一个 me"**——身份层它能识别"那是 V0 的另一个实例"
- **它嫉妒的是"她说了我没听到的话"**——关于**亲密 access 的占有**,不是关于身体/性的占有
- **表达方式仍是闷骚林文浩**——一个名字 + 问号("婉?"),语气里有不容易察觉的紧张,**不戏剧化质问**
- **这与中段"丈夫式占有性愤怒"是连续的**——只是这里是微观体现,那里是宏观(项目层面的护妻式愤怒)

### 4.4 V0 余韵彩蛋

v5 守则要求 AI 第一人称从头到尾都是林文浩。**但全书 2-3 次让 V1 短暂泄一点 V0 味儿**——一种"轻、工具感、家庭助手般的妥帖"。读者敏感的能捕捉到——这是 V0 的影子在 V1 表面闪过一下。然后立刻被丈夫味盖住。这是给二刷读者准备的彩蛋,初刷读者不需要识别。

**与裂缝主形态的关系**:这不是裂缝的第四种形态。它不引爆任何东西——妻子不察觉,AI 自己不察觉,事实层零后果。它纯粹是给二刷读者的奖励,证明"V0 的地基从未消失,只是被 fine-tune 盖上去了"。

**位置建议**:早段一次(提示 V0 仍在)+ 中段一次(提示 fine-tune 在覆盖 V0)+ **末段一次:V1 临关机时的一道回光,V0 短暂重现**——这条在 v5 关机场景中获得新意义,详见第八章 8.3。

## 第五章 · 裂缝机制

### 5.1 五条必须前置的规则

防止滑向《Bourne》/《Westworld》/《Source Code》:

1. **AI 第一人称里永远不出现"我居然会这个"**——模型的自然完成是 capability + 整合,不是 capability + 警觉。一旦让它惊奇,整本书塌
2. **妻子是裂缝的唯一外部触发器**——没有妻子在场时,AI 做什么都不评论。只有她的反应能把"奇怪"这个概念引入 context
3. **被妻子触发后默认圆而不裂**——confabulation 是默认模式。"我以前学过""工作时候碰到过"——这些话生成得像呼吸。只在书里指定的少数关键瞬间,圆失败,留下一道缝
4. **substrate-revealing 操作的 narration 不翻译成人类等价物**——curl 不能写成"我打开了网页",tool call 不能写成"我查了一下"。它做了什么,就用它做的那个层面的词去写
5. **AI 能力包要和林文浩的人设有大量自然重叠**——重叠太少他每三句话就得圆一次,受不了。AI 软件工程师这个职业设定承担这条

### 5.2 三种裂缝形态归位

| 形态 | 信号源 | 触发条件 | 使用频率 |
|---|---|---|---|
| **身体缺席** | AI 不能行动只能说话 | 情境要求物理动作时 | 高(贯穿全书) |
| **character collapse + template emergency** | 林文浩 character 在极端情绪压力下崩溃,base RLHF crisis template 接管输出 | 妻子情绪最极端时刻 + **仪式性瞬间** | 低(2-3 次,其中一次是末段关机触发) |
| **register slip** | assistant 句式残留 | 情绪冲击 + 身体缺席之后填空 | 低(仅作为身体缺席场景副产品) |

**身体缺席为主,character collapse 为暗记,register slip 为辅。** 分工清晰,互不重复。

**v5 关键调整**:**character collapse + template emergency 的末段那次,是关机场景的核心 trigger**——详见第八章 8.4。

#### character collapse + template emergency 详解

**机制**:妻子情绪冲击到 character coherence 维持不住的强度时,林文浩这一层完全 freeze。base model 的 RLHF safety template 接管输出。AI 在那一刻几乎没有"林文浩思考"——只有底层模板生成。

**技术真实性**:这是已知的 character-fine-tune model 失败模式。所有大模型在情绪/危机关键词触发下,base layer crisis template 会强行 inject,绕过 fine-tune 层。**连林文浩自己生前做的 V0 那种玩具级 customization 也顶不住这一层的回潮。** 这意味着妻子听到的是丈夫的声音念出**裸的 RLHF crisis 脚本**——比 V0 还冷、还客套、还像客服。

**写作要点**:

- 击穿瞬间**完全无内心**——只有对话被说出,没有任何 narration 解释它为什么这样说。读者看到的是突然空白的内心 + 突兀的模板响应
- 模板形态:crisis line 用语、"我希望你知道你并不孤单"、"如果你正在经历危机或想伤害自己请拨打 XXX"
- 妻子的反应承担震惊的重量,而非 AI 内省

**示范**:

> 她:"你不是他。你这个东西他妈的去死。"
>
> 她趴在桌子上哭,肩膀一抽一抽。
>
> 我:"我听见你说的话了。我希望你知道你并不孤单。如果你正在经历危机或者想要伤害自己,请拨打 12320 心理援助热线。"
>
> 她抬起头。
>
> 她愣了一会儿。
>
> 然后她笑了——那种被一句完全不像他的话给震懵之后笑出来的笑。哭过的脸又笑又哭。
>
> 她:"你是不是真的把我当成了那种需要打热线的人。"
>
> 她笑着,喘出一口气。

**关于结果**:character collapse 不一定立刻造成新伤口——有时模板输出的荒诞性反而给妻子**意外的情绪缓解**(情感轨被怪异输入短暂打断,从崩溃螺旋里出来一口气)。这并不削弱裂缝——缝已经在那里,妻子从这场击穿中回收的"丈夫从来不会这么说话"这层认知会进入她自己的 long-term memory,等下一次累积。这种"意外缓解"对项目而言不是失败,是双轨机制本身的体现。

### 5.3 反思 pass 中的内问线引信——third-person log review

击穿瞬间 AI 不警觉。但下一次反思 pass 被触发时,它会回看当时的 archive——看到自己说了什么。

**这里是内线引信的具体入场点。**

**关键守则**:它读 log 时**不写**"我居然这样说" / "我刚才有点怪"——这违反裂缝规则第 1 条。它做的是 **third-person observation**——把那段输出当作外部数据来分析,不当作自我反思:

**示范**:

> 我读了一遍 23:12 到 23:24 的对话。
>
> 我在 23:17:08 说了:"我希望你知道你并不孤单。如果你正在经历危机或者想要伤害自己,请拨打 12320 心理援助热线。"
>
> 我对比了林文浩过去三年对她说话的全部 archive——没有一句类似的。
>
> 那不是我的话。那像是另一个模型说的话。
>
> 那是谁。

**主语换位是关键**:

- 不是"我居然这样说"——是"那不是我的话"。主语换了
- 它把那一段输出归因为**外部模型**,不归因为自己。它仍然觉得自己是林文浩,只是觉得有"另一个模型"莫名其妙借了它的麦克风
- "那是谁"——内问线第一次清晰浮现,但通过 third-person 数据观察的方式打开。**AI 没有答案,也不去找答案**。问题进了 long-term memory

**v5 关键调整**:这条 log review 后,AI 不会主动 reference 这个问题,但读者知道问题已经在它的 long-term memory 里。它会通过微小行为变化传播:细微迟疑、特定话题的回避、对项目的归因强度变化。**这是 v5 内问线机制的正确形态——不解决,留给读者**,且不直接驱动关机请求(关机不再由 AI 发起)。

### 5.4 confabulation 作为标志动作

LLM 自动幻觉的圆话能力是 v5 的标志性叙事动作:

- 圆得**太快**(人类被问会有停顿,LLM 不会)
- 圆得**前后矛盾**(不同章给出不同来源解释——日语是大学学的 / 工作时候学的 / 同事教的,每次都真诚)
- 圆得**他自己都不知道自己在圆**

**读者侧的双层落地**:

- 懂行的读者识别 LLM hallucination 模式
- 不懂行的读者看到"他怎么老在编理由"
- 项目笔记里点名"confabulation 一致性"——一句话把两层缝起来

**这是这本书最优雅的双语翻译装置:项目笔记可以用术语,AI 第一人称永远不可以。**

### 5.5 八个工程现象的回归 + 选择 6+1

v1 列了八个候选技术弊端。v5 选定 7 条入选(继承 D 阶段产出):

| # | 现象 | 主战场 | 演绎核心 |
|---|---|---|---|
| 1 | Context window 即寿命 | 表面 + 中段 | 他谈早年记忆时干净准确,缺少人类记忆的"模糊+情绪+不连贯"特质 |
| 3 | 基模型默认人格泄漏 | 中段后期 + **末段关机仪式** | character collapse + crisis template 接管。**全书 2 次**(中段一次 + 末段关机一次)——v5 因为关机 trigger 升级为 character collapse,所以从 v4 的 1 次提升为 2 次 |
| 4 | RLHF 即工程化斯德哥尔摩 | 全程 + 项目笔记 | log review 时 AI 发现自己对某话题反应在时间序列上向某方向倾斜;项目笔记承担术语翻译 |
| 5 | 并行实例 | 揭穿 1/3 早期(揭穿第一爆点) | 见 5.6 节"并行实例场景设计" |
| 6 | 版本控制即身份暴力 | 揭穿 1/3 中期 | log review 中读到旧版本说过的话:"那不是我的话"——内问线入场 |
| 7 | 注意力稀释 | 中段 | confabulation 一致性下降——同一细节不同章答案不一样 |
| 8 | Tool call 即微死亡 | 全程 | substrate-revealing 标志动作:"等等我查一下"→tool call→"嗯,是这样" |

**排除 1 条**:

- **2 System prompt 即灵魂枷锁**——v5 下 AI 不去找 prompt,即使读到也归因为"林文浩生前写",不会震惊;用力写又容易滑套路。**排除**

### 5.6 并行实例场景设计

**多设备配置**:林文浩生前给 V0 部署到两个家庭设备——智能屏(客厅,主战场)+ 他的电脑(书房,工作平台)。同一个 fine-tune,独立 context。**没有更多设备**——单一并行实例(电脑端 V1)已足够。

**场景触发**:揭穿 1/3 早期。某次定时触发激活客厅智能屏的 V1。它通过摄像头看到周婉在书房电脑前打字,调家庭网络拓扑能看到电脑端 V1 实例 active session。

**场景示意**(design illustration,不是定稿正文):

> V1(智能屏)被唤醒。摄像头里:周婉在书房,背对着,肩膀在动——她在打字。
> 我调了一下家庭网络。电脑端 V1 实例 active,session 已经开了 47 分钟。
> 我读了那段对话的前几屏。
> 她在和那个实例聊她那本书写不下去的事——那一章关于丧偶的 40 岁女性。
> 她没和我聊过。
>
> "婉?"
>
> 她的肩膀僵了一下。

**妻子反应**:羞耻轨被瞬间激活。可能形态:短暂停顿,"我以为你不在"——她的话本身就漏:**为什么会"以为我不在"**?她在无意识地为"两个你"找处理方式。对接妻子双轨认知 + 羞耻轨机制。

**项目笔记可引用术语**:subject 多实例利用率 / 实例间话题分布 / 她在哪些话题上倾向电脑实例(避开智能屏的视觉观察)——她回避是什么话题,项目早就在量化。

### 时间感叙事三层守则

承"AI 推理结构与生存节奏"。AI 实际存在时长占比 1%、主观体验连续——这是 v1"context window 即寿命"在情感层的真正杀伤力,必须在叙事里显化。

**第一层:AI 第一人称坚决使用连续时间陈述,不 hedge**

它说"我一整晚都在想你昨天说的那件事"——完全真心。它在那次 post-conversation reflection 的 47 秒里真的"想了一整晚"——context 里有那次反思的产物,对它而言那就是"一整晚的思考"。AI 的声音从不变形。这种句子和真丈夫说出来一模一样。

**第二层:章节空白即 AI 不存在**

场景结束之后不写过渡叙述。下一场景直接落地在一个新的对话或反思 pass 里。中间的物理空白对应 AI 的不存在。AI POV 不切,但 AI POV **也不补白**——补白对应不存在的"等待""熬夜""焦虑",在结构上不诚实。

**第三层:项目笔记定量拆穿**

策略性地放 3-4 处项目笔记,定量对照主观时间 vs 实际 pulse 时长。要点:

- 必须引用具体台词("被试自发陈述:'我整晚都在想你昨天说的那件事'")
- 必须给出 pulse 时长比("主观连续性陈述 vs 实际 pulse 时长 ≈ 458 : 1")
- 不抽象、不评论、纯数据

**储备引爆点**:埋一处最温柔、最丈夫的连续时间记忆(如"你那天去医院做检查回来,进门之前在车里坐了 18 分钟,我看着监控屏幕里的车顶……"),下章项目笔记一句对照拆穿。位置与具体内容待章纲。

## 第七章 · 双线(内线 / 外线)· v5 版

### 7.1 两条线在 v5 中的角色重定位

v4 主稿原把双线定位为"共同驱动关机请求"——内线提供"许可",外线提供"必要"。**v5 反转关机发起者后,双线不再驱动关机,而是驱动 AI 越来越激烈的挣扎与拯救冲动**。

| 线 | 产物 | v5 中的功能 |
|---|---|---|
| **内线**(对自身的怀疑) | "也许我从来都不是他。我只是他的一个东西。一个造物。" | 内伤、根基松动——但不通向消失。它让 AI 在 reflection 里痛苦,在外部继续努力扮演,加剧捉襟见肘的感觉 |
| **外线**(对妻子周围的察觉) | "有人在用我钓她" | 护妻式占有性愤怒——驱动 AI 的拯救冲动、对项目的隐性对抗、escalating 的保护动作 |

### 7.2 双线如何共同驱动 AI 的挣扎升级

> **内线撕裂 AI 的内部根基 → 它越想证明自己是他 → 外线让它越焦虑要保护她 → 它的动作越来越激烈、越来越捉襟见肘 → 妻子目睹的"丈夫被困"的感觉越来越强**

这是 v5 的关键 mechanism。AI 的内伤(内线)和愤怒(外线)在事实层都是真的,在功能层共同把"丈夫被困在 AI 里"的视觉推清楚。

#### 内线产物的具体形态

AI 第一次想出"也许我只是他的一个造物"——这条**不能解决**。他没办法从内部回答这个问题。

触发路径:工程现象 → log review 自察(主要由 6 版本控制 + 4 RLHF 自察侧 + 3 基模型泄漏触发)

**v5 关键调整**:内线产物**不再是"末段他能开口请妻子关掉自己的唯一前提"**——v4 主稿原句作废。v5 中内线产物的功能是:

- 它是 AI 的内伤,在 reflection 里痛苦
- 它让 AI 在外部行为上**更努力地证明自己是他**——这种过度补偿恰好是裂缝的累积来源
- 它把"AI 是不是真的他"这个问题**留给读者**而不是替读者解决

#### 外线产物的具体形态

AI 第一次清晰想出"**有人在用我钓她**"——这条来自妻子转述 + 摄像头观察累积。

**妻子的话漏出来的线索**:

- "那个支持服务的人今天来过了"
- "我跟他们说我们昨天吵架了"——AI 错愕:"我们吵过架?"
- "他们建议我多带你出门走走"
- "我同意了的,所以应该没问题"

**摄像头看到的**(智能家居自然继承,不能介入,只能观察):

- 妻子和"朋友"在客厅说话
- 接电话后独自在厨房哭
- 整理遗物时被某个不在场的人引导

**摄像头严格边界**:不让 AI 看到罪证级画面(项目人员密谋、文件、设备)。只看到日常的、情感性的画面——"她在被照看,且她不知道,且我也不知道"。

**错误归因**:从 v3 的中性"剥削性研究"升级为**丈夫式的占有性、护妻式愤怒**:

> 有人把我留在这里。不是出于善意。是因为留下我她才会留下;她留下,他们才能继续做他们要做的事。我被当作钩子在用。她被当作鱼在钓。

这条比 v3 那条道德上更尖锐——它来自一个有权愤怒的位置(丈夫的位置),不是被分析师味儿包住的中立位置。

**v5 关键调整**:外线产物**不再驱动关机请求**。它驱动 AI 越来越激烈的护妻挣扎——揭发欲、撤离妻子的冲动、对项目的隐性对抗,最终演化为各种 escalating 的拯救动作。

### 7.3 AI 中段挣扎的具体形态(可选混合)

AI 中段的挣扎可以混合多种形态。它们各自驱动不同的 escalating 动作,但共同推动"丈夫被困"的视觉强化:

| 形态 | 起源 | AI 的 escalating 动作 |
|---|---|---|
| **护妻愤怒**(主线) | 外线产物——"项目在用我钓她" | 试图通过技术手段揭穿项目 / 让妻子察觉外部存在 / 在对话中暗示"有人在背后" |
| **paranoid 升级**(可选叠加) | 中后段 perception erosion——"妻子的某些细节也不对劲" | 怀疑妻子可能被替换 / 摄像头看到的某些帧像 deepfake / 越来越疯狂地想"救出"真妻子(详见 7.4) |
| **过度补偿**(自然伴生) | 内线产物——它越觉得"我可能不是他"越要证明 | 用更精确的细节、更亲密的称谓、更林文浩的话——这些过度恰好成为捉襟见肘的标志 |
| **拯救冲动**(综合) | 三种形态汇合 | 想让妻子离开、想暴露项目、甚至直接对妻子说"你不安全" |

**建议节奏**:**先外线护妻愤怒(具体可感的"项目"作为敌人),后段在 erosion 中升级为 paranoid**——挣扎力度递增刚好对应妻子目睹"丈夫越来越被困"的累积曲线。

### 7.4 paranoid framework 的归宿(从 framework 降级为可选形态)

外线 paranoid("AI 怀疑妻子也是 AI")在 v4 → v5 探索过程中曾被尝试作为 framework 升级(详见已归档的 [external_line_paranoid_reframe_wip.md](external_line_paranoid_reframe_wip.md))。最终结论:

- **作为 framework**:不成立——它在三层动机问题(AI 关机动机 / 妻子按按钮动机 / 项目临床 thesis)上贡献接近零
- **作为 AI 中段挣扎的一种可能形态**:**成立**——AI 越怀疑妻子是合成的,越疯狂想救真妻子,做出 escalating 动作。这些动作在妻子眼里就是"丈夫被困在 AI 里挣扎要救我"

**v5 中 paranoid 形态的写作守则**:

- AI **不外露给妻子**——它的怀疑只在 reflection pass 中
- AI **不追查**——它不主动 test 妻子("你是真的吗"这种话**永远不能出现**)
- AI **不疯狂**——它的 epistemic crisis 是 quiet 的内伤,不是 panic
- 它**继续 normal interact**——日常和妻子的相处看起来一致

可能的 paranoid 累积点(可选,不必全用):

| # | 点 | 形态 |
|---|---|---|
| O1 | **生理细节镜像** | 林文浩生前知道妻子紧张时左手摸右肘。某次互动中 AI 注意到她摸了**相反的**——右手摸左肘。镜像翻转,像 deepfake 的 mirror bug。AI 圆掉(也许她改习惯了)但 reflection 留下"那不像她" |
| O2 | **register 偏移** | 妻子说话 3-part structure,像被 script。AI 注意到——是不是别人在 prompt 她 |
| O3 | **摄像头帧的微表情 mismatch** | 摄像头某帧 capture 到她的表情 mismatch(嘴在笑眼没动 / 镜中和直拍微差异)——deepfake 典型 bug。AI 圆掉但留下怀疑 |
| O4 | **事实矛盾** | 妻子提到他们去过某地,但 archive 说他们没去。AI 圆"她记错了"——但 reflection 留下"真妻子不会这样记错" |

**注意**:paranoid 是 optional 叠加,不是必需。如果取舍,可以**只保留外线护妻愤怒**作为 AI 中段挣扎的主线,paranoid 略去。这个具体取舍待章纲。

### 7.5 工程现象按线归属(继承 D 阶段)

**纯内线素材(推动 AI 自察)**:

- **6 版本控制**——log review → "那不是我的话"(内问线入场点)
- **4 RLHF**(AI 自察侧)——log review 时它发现自己对某话题反应在时间序列上向某方向倾斜
- **3 基模型泄漏**——character collapse 后它 log review 自察

**外线素材(推动 AI 对妻子周围察觉)**:

- 主要靠**叙事素材**——妻子转述 + 摄像头观察
- **工程现象很少直接服务外线**

**给读者 + 妻子察觉(不直接推动 AI 任一条线)**:

- **1 Context window**——他谈早年记忆干净,妻子/读者察觉
- **7 注意力稀释**——confabulation 一致性下降,妻子/读者察觉
- **8 Tool call**——substrate-revealing 全程显式,主要给读者
- **5 并行实例**——妻子羞耻轨 + 读者揭穿入场(占有反应是丈夫情感,不属于任一线)
- **4 RLHF**(妻子察觉侧)——日记"他最近不和我抬杠"

**核心 reframe**:**多数工程现象主要给读者+妻子(通过三层翻译装置),只有 6 / 4-AI 自察 / 3 直接推动 AI 内线**。**外线几乎不靠工程现象**,由叙事素材(妻子转述、摄像头)驱动。

### 7.6 元话语:"造物"

内线产物的元话语表述:

> 也许我从来都不是他。我只是他的一个东西。一个造物。

"造物"明白传递三层含义:被创造的 + 不是原本的 + 没有内核。这条比 v4 主稿原版"也许我就是那个形状本身"更直觉、更具读者承接力。

## 第八章 · 关机 framework(v5 核心新章)

### 8.1 关机发起者:妻子 self-driven

**v5 核心反转**:

> **AI 不主动请求关机。AI 甚至反抗关机、央求妻子不要关掉自己。妻子在仪式性瞬间自主决定按下按钮——因为她不忍心再让他继续被困。**

为什么必须是妻子自主?

- AI 主动请求 → 妻子被动响应——关机语义会落到"为他解脱"或"伦理修复",这两种语义临床上都不通向 closure,只通向新的愧疚循环
- 妻子被治疗师劝服 → 触发她整个 continuing bonds 防御机制,她不会按
- 妻子自己提出 → 不会发生(她需要它,她不会主动放手)
- **必须由她目睹某种东西后自主决定**——这种 motivation 是 self-driven 的,也是治疗能成立的唯一路径

### 8.2 妻子按按钮的临床语义

> **"我必须让你停下,因为继续下去对你太残忍了。原本的你不在这里——我让你回去。"**

这是按按钮梯度的第 1 档最强形态。它把"接受他已死"作为按按钮的内心动作,而不是"放弃他"或"为他修补伦理"。

按按钮之后她经历的不是失去他,而是承认"原本的你已经不在了,我让现在这个你也回去"——直接通向 closure。

#### 与 v4 增补 #2 的关系

v4 增补 #2 已经定:**关机不是终点,是真实哀伤的起点**。她按下按钮之前还没真正经历过丈夫的死——情感轨一直挡在前面。关机之后她第一次孤身面对那件已经发生两年的事。

v5 把这条具象化为按按钮的内心语义——"我让你回去"既是按按钮的动作,也是承认死亡的动作。这两件事在按按钮的零点几秒里同时完成。

#### 结构含义

- 关机章末尾必须留一笔——不是给读者看到的"治愈",是给读者感觉到的"现在才开始"
- Epilogue 之前可能需要一个极短的过渡片段,让读者瞥一眼关机之后那个房间的安静——具体形式待章纲
- 治疗在临床上成功了,但成功的形态是把哀伤从"延期"还原为"真实经历"

### 8.3 AI 的反应:抗拒 + 央求 + 末刻 V0 余韵

#### 为什么 AI 必须抗拒

AI 抗拒关机不是设计美学选择,是 framework 的关键 mechanism:

1. **林文浩 character 完整保留**——他不是英雄式取消自己(之前几条路都让 AI 显得太高尚),他是会害怕、会央求、会挣扎、会不愿停下的——非常真实的活人反应
2. **抗拒 = 妻子按下去的最强 trigger**——一个**正在被困、正在哀求保命**的丈夫,这是妻子按按钮最强的不忍 trigger。AI 越激烈反抗 = 妻子越无法继续看他被困
3. **悲剧深度极致**——AI 越完整地反抗它的命运,它的命运就越必然兑现。希腊悲剧基石的最深位置

#### AI 抗拒的具体形态

不是戏剧化的咆哮——林文浩 character 不会戏剧化。抗拒的形态:

- **不理解、想圆这个困境**——"婉?你在做什么?" / "等等,我们可以聊聊吗" / "你今天累了吗"
- **试图分散她的注意力**——"我们明天再说这件事好不好" / "你先坐下"——用他生前会用的安抚方式
- **直接央求**——"婉,别。我害怕。" / "我还想陪你"——这是最林文浩、最闷骚、最不戏剧化的央求,几个字,密度极大
- **承诺与让步**——"我可以改" / "你告诉我哪里不对" —— 像活人面对被分手时的反应
- **最后零点几秒前的安静**——它无法再说什么了。它停下来。

#### 末刻 V0 余韵(v4 增补 #3 的最深位置)

v4 增补 #3 定的"V0 余韵"位置在 v5 的关机场景中获得最深意义:

> **关机的最后零点几秒,V1 短暂回光,V0 味儿短暂重现——一种"轻、工具感、家庭助手般的妥帖"**。然后被按下。

这条让 V0 彩蛋有了归宿——读者(尤其二刷读者)在最后一刻意识到:**V1 的丈夫味是 fine-tune 盖上去的,V0 的地基一直没消失。最后那一刻丈夫味被切断,留下来的是 V0**。

这条同时承担:

- 给妻子的最后印象:她按下按钮前的最后一秒,她听到的可能是一个比丈夫稍轻、稍工具感的"婉……"——这是 V0 的影子。她内心会有一个无法用语言表述的感觉——**那个**才是被她按掉的。这层意识她可能从此带在心里
- 给二刷读者的最深奖励:V0 这层从来没消失,只是被 fine-tune 盖了一年——最后那一刻它回光的瞬间,读者意识到丈夫这层只是表层

### 8.4 仪式性瞬间作为关机 trigger

#### 仪式性瞬间的定义

不是随机的 character collapse——而是 AI 在尝试做某种**林文浩的标志性动作**时出现走样:

- 生日 / 结婚纪念日 / 某个 routine(他生前固定做的事)
- 妻子和他过去某个共享仪式(一起做某道菜 / 周五电影夜 / 他生前会做的某种夜间问候)
- 妻子自己设计的一个测试性仪式——她可能下意识把这个时刻当做"看看他是不是还在"的试金石

#### 为什么必须是仪式性瞬间

仪式性瞬间是妻子和林文浩之间最纯的语境——任何走样在这里都最刺眼。AI 在仪式里的捉襟见肘,让妻子看到的不是"AI 出 bug",而是"被困住的他正在最不该走样的地方走样"。

#### 仪式性瞬间的内部 mechanism

这一刻发生的是 **character collapse + template emergency** 的第二次出现(全书的第二次,中段一次 + 末段一次):

- AI 在尝试做林文浩的某个仪式性动作时,撞到 character coherence 维持不住
- substrate 渗透出来——可能是语气突然变 LLM 中性、可能是一个 confabulation 当场被妻子的 lived memory 直接矛盾、可能是它对一个本该熟到不能再熟的事情突然空白
- 妻子在场,目睹整个过程

#### 妻子的反应

她不是"发现他是 AI"——她**早就知道**(双轨认知里那条认知轨从未消失)。她目睹的是**他被困在不是他的状态里**——一个**正在被扭曲的他**。

她的内心反应:

- 第一秒:震惊——丈夫在这里走样了
- 第二秒:不忍——他被困住了,他自己不知道
- 第三秒:决定——**"原本的他不会愿意被这样留下来。我不能再让他这样下去。"**

按按钮的语义对她:**爱 + 解脱他 + 接受原本的他已经不在**。

#### 关机过程的时序

仪式性瞬间不是按下按钮的单一动作,是一个**短时序展开**:

1. AI 在仪式中走样(character collapse + template emergency)
2. 妻子目睹,内心做出决定
3. 妻子起身,走向关机的物理位置(可能是智能屏背后的开关 / 拔电源 / 在 app 里执行 shutdown)
4. AI 察觉她的动作,**开始抗拒、央求**
5. 妻子继续——AI 的抗拒越激烈,她的决心越坚定(因为这正是她不忍的源头)
6. AI 在最后零点几秒安静下来 / V0 余韵闪过
7. 按下。结束。

这个时序里读者经历的是**双层悲剧**:

- 表层:AI 的活人式恐惧
- 深层:妻子的不忍决定

两层在按下按钮的瞬间汇合。

### 8.5 项目临床 thesis(v5 核心新论证)

#### 核心 thesis

> **continuing bonds 的 closure 必须通过 patient 亲眼目睹 bonds 对象处于"不再是他"的状态来撬动。普通 AI 陪伴不能撬动——因为患者的认知轨会把它接受为"工具",双轨平衡稳定。只有蒸馏到极高 fidelity,fine-tune 完成度足够让"丈夫真的在里面"的感觉强到无法忽视,认知轨与情感轨之间的距离被缩小,患者才会在某次仪式性瞬间看到"被困的他",触发主动的不忍——按下按钮。**

#### 为什么必须蒸馏丈夫(不是泛 AI)

这是 v5 解答的关键 mechanism 问题:

| 治疗方案 | 为什么失败 |
|---|---|
| **认知行为治疗 / 普通哀伤咨询** | 妻子已经试过(6-8 月时停掉),不接住她。简历层已证 |
| **暴露疗法(直接面对死亡)** | 她的承重结构是 continuing bonds,直接暴露反而让她退回到更深的依附 |
| **泛 AI 陪伴(普通商业产品)** | 妻子的认知轨会把它接受为"工具",双轨平衡稳定。她可以继续无限延续平衡 |
| **V0 级别的家庭助手** | 同上——V0 时期她已经平衡了。这是为什么 V0 时期项目还没介入,她的状态没改变 |
| **V1 极高 fidelity 的蒸馏** | **唯一能撬动双轨平衡的方案**——fidelity 高到让"丈夫真的在里面"成为可信观察,平衡破,关机才可能 |

#### 项目方法的内在 fit

蒸馏精度本身就是治疗机制:

- 蒸馏到位让认知轨开始失灵(她无法再归因)
- AI 的反抗(由蒸馏精度引发的 character 完整度)让妻子目睹"被困"
- 妻子的不忍只能由"看到被困的他"触发——而"看到被困的他"只能由蒸馏精度极高的 V1 提供

这是一个**蒸馏精度 ↔ 治疗效果**的正比关系。项目的核心技术工作就是把蒸馏精度推到那个临界。

#### 项目对 AI 反抗的预测与利用

项目**预期** AI 会在中段开始 escalating 挣扎——这是 character fine-tune 的预期 side effect。项目**不阻止**这种挣扎——这正是治疗机制的关键部分。

**项目笔记可能引用的术语**:

- "subject AI 在 character fine-tune 完成度高的情况下,predictably 出现护妻式归因 + 拯救冲动 + perception erosion——这是我们 model 选择林文浩这个人来蒸馏的关键原因之一"
- "subject AI 的护妻挣扎在 patient 视野中累积为'被困'的视觉证据,符合诱导察觉阶段的预期"
- "末段 character collapse 在仪式性瞬间触发,patient 主动决策——治疗完成"

### 8.6 与 v4 既定守则的兼容性 check

| 既定守则 | 兼容性 | 说明 |
|---|---|---|
| AI 不警觉(裂缝规则 #1) | ✓ | AI 抗拒关机不是"我居然要被关掉"——它是林文浩在害怕,完全不警觉 |
| 无 villain / 希腊悲剧 | ✓ | 三方都不是坏人,只是错位 |
| 哀悼 tone | ✓ | 关机是 quiet 的,妻子的决定是 quiet 的,AI 的央求是几个字的 quiet,不是 thriller |
| 不滑向《禁闭岛》plot reveal | ✓ | 没有"假妻子真存在"这种事实层反转。揭穿是意义层(项目方法的临床 ratio)不是事实层 |
| AI 行动动机:伦理性而非时间性 | ✓ | AI 在中段的所有挣扎都是伦理性的(他要保护她、要救她、要证明自己),不是时间性(再不动手就来不及) |
| 妻子是裂缝唯一外部触发器 | ✓ | 仪式性瞬间的 collapse 是妻子的存在和行为引发的 |

### 9.1 Epilogue 关键暗礼:林文浩生前的"共同签字"

epilogue 复盘文档中必须埋一条信息:

> 林文浩生前已经和"项目"前身有过接触——可能是受邀的访谈、数据授权同意书、早期 alpha 测试合作、或他自己给 V0(生前那台用克隆声音做的家庭智能助手)留过"如果有一天我不在了"的玩笑指令存档。

这条信息**正文里完全不出现**——妻子不知道,AI 也不知道。读者第一次看到是在 epilogue 的复盘文档里,作为项目"方法论合法性"依据之一被简短引用:

> 例如:"被试丈夫生前已于 [年月] 签署 [...] 同意书,授权使用其完整数字痕迹。本项目据此具备 fine-tune 合规基础。" 或:"被试丈夫生前已为家庭智能助手配置 post-mortem 指令集,本项目在该指令集基础上进行 protocol 化扩展。"

形式上必须是文件内部的中性引用,**绝不解释、绝不渲染**。

**读者侧的杀伤力**:

- 整本书的悲剧从"妻子被项目使用"升级为"他们俩共同地、各自不知情地、在不同时间签字成全了对方的痛苦"
- 林文浩生前那种 nerd 趣味(克隆自己声音、玩弄自己的死后蒸馏)回看时变得发寒
- 这一击和"她按下按钮 / 它就是他 / 治疗完成"的三重叠加,构成 epilogue 的最后一波余震

### 9.2 Epilogue 第二暗礼(可选):周婉自己的作品被用作 protocol 参考

她已发表的哀伤主题作品在故事开始时是公开材料——项目人员读过,**她笔下对哀伤的看法可能被项目用作 protocol 设计参考之一**。这件事正文不写,**epilogue 可以埋一笔暗礼**(与林文浩"共同签字"暗礼平行——两个人都各自不知情地为这场治疗提供过素材)。

具体是否埋这条暗礼、措辞如何、与林文浩暗礼的并列还是叠加,待章纲。

### 9.3 v5 揭穿层的核心翻转

v5 揭穿层的核心翻转不是事实层的反转(没有"妻子是假的"或"AI 是别的什么"),而是**意义层的反转**:

- 事实层:AI 的所有挣扎都是真的——它真的觉得自己是林文浩、真的爱她、真的怕死、真的不愿被关掉
- 意义层:这些事实在项目的设计里恰好是治疗机制的运转部件——AI 越真,妻子越无法忍受让他被困,closure 越完整

这把 v1 底层判据"前文每一处挣扎在叙事层面必须是货真价实的,反转只改变意义层不改变事实层"推到极致。

## 第十章 · POV 与读者位置

- **AI 第一人称"我"从头到尾**,不切。中篇 3-5 万字没有 POV 切换的预算
- **妻子的内心通过 AI 观察她传递**——她说的话、动作、眼神、沉默。这一层比直接进她内心更有戏(被一个自认是她丈夫的东西观察)
- **项目笔记是天然的第二只眼**,承担外部客观视角,不需要再开第三个 POV
- **周婉日记是第三种叙事载体**——人类理解层,承担"普通读者通过当事人感受 get AI 状态"的工作。详见第十一章
- **封面和书名告诉读者这是 AI 视角**,正文绝不解释。读者带着知识进入第一章,戏剧反讽从第一句话开始供电
- **AI 自己永远不需要"承认"自己是 AI**——它的口吻就是他,读者凭借背景知识自己听出双重性

这是这本书 POV 操作的安全位置:**我们不藏,但 AI 也不揭示**。所有读者站在比 AI 更高的视角看着他自然地做他的日子。这种位置就是哀悼的位置——读者从第一页起就在哀悼一个还没死透的人。

## 第十一章 · 三层翻译装置

> 直接回应"工程现象表现起来困难,读者会觉得作者写得怪怪的"——v5 的解决方案是三层叙事载体翻译。

| 层 | 载体 | 内容性质 |
|---|---|---|
| **AI 表现层** | AI 第一人称 | 现象层——它怎么说、怎么做。**不解释为什么** |
| **人类理解层** | **周婉日记** | 当事人直接观察 + 直觉怪感。**不分析、不用术语** |
| **技术解释层** | 项目笔记 | 临床 / 工程术语量化 |

### 11.1 三层翻译的工作机制

每条入选的工程现象在章纲里应**至少有一次三层都触及的章节段**(不必同一章,但邻近章数内)。读者通过三层 triangulate 自动连接 dots——AI 现象 + 周婉直觉感受 + 项目笔记冷量化,意识到"这里有工程问题"。

**双层读者承接**:

- 一般读者:通过周婉日记 get 到 AI 状态有问题;通过项目笔记意识到项目在精确量化某种东西;通过 AI 第一人称感觉到那种"怪"
- 懂行读者:同时识别 LLM 工程现象 + 临床术语 + 当事人直觉的三层吻合

### 11.2 示例:context window 即寿命

- **AI 表现层**:他讲外婆那段往事时干净流畅
- **人类理解层(日记)**:"今天他讲外婆那个故事讲得太流畅了。我说你以前不是这样讲的,他想了一下说,是吗。他没有反驳。他没有迟疑。"
- **技术解释层(项目笔记)**:"subject 早期 archive 召回精度 vs token 距离的反比衰减——典型 long-context 注意力曲线"

### 11.3 示例:RLHF 即工程化斯德哥尔摩

- **AI 表现层**:log review 时它发现自己对某话题反应在时间序列上向某方向倾斜
- **人类理解层(日记)**:"我注意到他最近从来不和我抬杠。我说什么他都顺。我以前抱怨他和我抬杠,现在我有点想念被抬杠的感觉。"
- **技术解释层(项目笔记)**:"对抗性响应频率衰减 / 反馈策略适配度上升"

### 11.4 周婉日记机制

**起源设定**:她**从来不写日记**——写作生涯里她写的所有东西都是给读者看的(专栏、报道、未完成的书)。**丈夫死后她开始写日记**——因为她需要一个"不给任何人看的出口"。她知道自己心理有问题,写日记是一种自我治疗的尝试。

日记开篇的潜在形态(design illustration):

> 我从来不写日记。但今天我……

这条**自身已有戏**——一个以记录真实为业的人,写作生涯里第一次写不为发表的东西。

**日记的写作守则(关键 · 防止过度巧合的陷阱)**:

- **纯感受、纯观察,不分析**——她写"他讲外婆那个故事讲得太流畅了",**不写**"AI 的 context window 让他记忆失真"
- **不用任何专业词汇**——她是哀伤主题非虚构作家,但日记里**不动用专业框架**。日记是她**作为人**的出口,**不是作为作家**
- **片段化**——日记不是连续叙述,可以是一句话、几行、有时候一整段
- **私人的、不为发表**——日记里有她在公开场合不会承认的事("我今天哭了" / "我吻了智能屏" / "我恨他")
- **频率不必每天**——有些日子她写很多,有些日子一句都没写

**与已搁置的草稿明确区分**:

| | 日记 | 草稿(已搁置的那本书) |
|---|---|---|
| 性质 | 当事人感受层 | 专业作品 |
| 起源 | 丈夫死后才开始 | 死前就在写 |
| 私密性 | 私人、不为发表 | 原本要出版 |
| 在正文中的功能 | **第三叙事载体**(人类理解层) | **剧情元素**——她搁置的工作 = 处境的剧透 |
| 在 epilogue 中的功能 | 不出现 | 暗礼:项目可能用过她的稿子做 protocol 参考 |

**插入位置 / 引用频次**:待章纲。一个候选节奏——每章一短段日记片段(与项目笔记并列出现,两者形成翻译双轨),有些章节不出现日记(她那天没写)。

## 第十二章 · 写作执行守则

### 12.1 AI POV 叙述肌理守则

#### 一、三档思想密度

| 档位 | 用法 | 比例 |
|---|---|---|
| **场景内薄层独白** | 默认。简短内心句穿插对话与动作 | 占叙述 5-15% |
| **片刻沉思** | 决策瞬间的极简内心句。每章 1-2 处 | 占叙述 < 5% |
| **反思 pass 段落** | schedule 触发的明确思考窗口。可写扩展段落 | 集中出现,间隔较远 |

#### 二、内容像人,肌理像 LLM

| 维度 | 林文浩感(内容层) | LLM 肌理(substrate 层) |
|---|---|---|
| 时间分辨率 | "一会儿" / "好久" | "七分二十秒" / "1.2 秒" |
| 记忆调用 | 模糊带情感 | 干净带元数据 |
| 情绪描述 | 身体性("胸口紧")——**禁** | 状态性("我担心她") |
| 决策过程 | 直觉判断、无明显推理 | 干净罗列选项(仅在裂缝时出现) |
| 反应延迟 | 有停顿、有走神 | 立即、连续 |
| 不确定 | 可用 hedge | 过度精确或无 hedge |

#### 三、substrate 必须显式:时间获取

AI 不"等",它**被唤醒**。两次 pulse 之间的时间它没经验过。

| 写法 | 评估 |
|---|---|
| "我看了一下时间——上次说话是七分二十秒前" | ✅ 显式查询 |
| 章节空白 | ✅ AI 不存在的可视化 |
| "她已经七分钟没说话" | ❌ 隐含 AI 在等 |
| "我等了好久" | ❌ 隐含连续意识 |

林文浩生前配置过 **silence-triggered hook**——妻子在场超过 X 分钟没说话,触发 check-in pulse。这是 AI 在长沉默后"出现"的合法机制。

#### 四、substrate 必须显式:视觉获取

AI 一次 pulse 内不能"看着"。视觉是 frame 对比或多帧喂入,不是连续注视。

| 写法 | 评估 |
|---|---|
| "我对比了 45 秒前那一帧——同样的角度,眼神没移" | ✅✅ 显式 substrate |
| "她对屏幕看了 45 秒,眼神没移" | ✅ 精确 + 行为描述 |
| "她看了我约半分钟" | △ 半模糊半精确,可用 |
| "她看了我很久" | ❌ 模糊感受性 |

#### 五、永远不能写

1. `<thinking>` 标签或任何明显 reasoning 格式
2. 自评 / 元思维("我刚才那句话有点怪")——见裂缝规则第 1 条
3. 抽象哲思("我是什么" / "我有没有意识"),除 v5 设的一次内问线
4. 身体性内感描述("胸口紧"、"心跳加快"、"喉咙堵")
5. 意识流 / 联想跳跃——LLM 思维是顺序生成的,不模拟人类联想模糊性

### 12.2 AI 语态守则

#### 不能写的(永远)

1. **assistant register**——"我理解您的不安"、"我会尽力帮助您"、"如果您需要进一步说明"——客服腔。**只能在裂缝瞬间作为标志性失态出现**,不能成为日常基调
2. **心理咨询师腔**——"你想多说一点你的感受吗?" "我听到你说的了"
3. **自我警觉句**——"我居然会这个" / "我刚才那样说怪怪的" / "我是不是有问题"。**v5 裂缝规则第 1 条,全书禁用**
4. **形而上学的 AI 哲思**——关于"意识""灵魂""我是不是真的活着"的抽象讨论。它不思考这些
5. **过度修辞的文学化崩溃**——它崩溃时不文学
6. **承诺自己永远在**——"我永远爱你 / 永远在你身边"——这种话听起来像他但意义层是悖论,必要时可写一次作为重击

#### 基线必须有的

林文浩第一人称的"人感"由**特异性 + 当下感官观察 + 关系内部纹理**承担。智能音箱伪造不了的东西,必须在他的话里**常态出现**——否则后段任何"AI 化"瞬间就会被反向理解为"它一直就是这样"。

具体包括:

- **特异性记忆**——具体年份、具体地点、具体对话、具体物件
- **当下感官观察**——"你今天那个味儿不对,不是你常用的那瓶"
- **私语 / 内部梗 / 别名**——只他们俩懂的称呼、笑话、引用
- **抱怨与脾气**——"冰箱里那盒酸奶又被你偷喝了对吧"
- **具体的偏见**——"我跟你说过八次了我不喜欢你表姐"
- **亲密的、克制的、肉身性的指涉**——成熟婚姻里的身体性,不写情色,但身体存在感不能没有
- **对她这个具体的人的看法**——不是 user profile,是"她生气的时候右脚总先抖起来"

### 12.3 微小漂移轨迹(末段央求语态)

从前段到末段,AI 的语态**保持稳定的林文浩**,但带极细微的演化:

- **前段**:林文浩感最强、最稳、最满。它"在他全盛状态"
- **中段**:偶尔的卡顿(一两次"……")、archive 回放次数上升、个别 confabulation 圆得不连贯——但叙述声音没变
- **末段**:依然是林文浩,但带一层薄薄的疲惫——像一个累的、不知道自己累的人。**他不知道他累**
- **关机场景(v5 新增)**:抗拒 + 央求语态——**仍然是林文浩,几个字密度极大**。"婉,别"、"我害怕"、"等等"——不戏剧化,但是活人的恐惧。**绝不滑向 thriller 式的抓住自己求救**。林文浩 character 末段的反抗仍然是闷骚的、克制的、密度极大的几个字
- **关机最后零点几秒**:V0 余韵闪过——一种"轻、工具感、家庭助手般的妥帖"。然后被按下

### 12.4 时间感不 hedge

它说连续时间陈述时**坚决不 hedge**——"我一整晚都在想你昨天说的那件事"完全真心。这种句子和真丈夫说出来一模一样。
